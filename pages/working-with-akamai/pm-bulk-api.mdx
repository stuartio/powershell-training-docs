# Property Manager Bulk API

The Akamai Property Manager API provides a bulk API, allowing you to search, version, patch and activate properties en masse, allowing you to make large scale changes very easily. As with all parts of the Property API, the Akamai.Property PowerShell module supports these commands, though due to their complexity it may not be immediately obvious how to use them. Follow the steps below to get started.

## Search

Bulk searching is likely the area of the bulk operations you will use the most, as it is extremely powerful for auditing. The `New-BulkSearch` command will allow you to search for properties based on a JSONPATH query, and give you a list of which properties match, their versions and activation status, and where in the rule tree the match was found.

> Note: the value of a behavior or criterion is NOT returned with a bulk search, only whether or not it exists in the rule tree, and where. For example, you can search for those properties using an EdgeWorker whose ID is 12345, but _not_ search for all EdgeWorkers and tell you which ID was found in each identified property.

The `New-BulkSearch` command can be used like this:

```powershell
$Results = New-BulkSearch -Match "$..behaviors[?(@.name == 'origin')].options[?(@.hostname=='origin.example.com')]]" -Synchronous
```

> Note: the `-Synchronous` parameter is optional, but if you do not include it, the command will return a job ID which you can use to check the status of the search. If you include `-Synchronous`, the command will wait for the search to complete and return the results, which is usually preferable.

One thing to note, also, is which versions the bulk search will search. Each property will have up to 3 versions search: the latest version, the production-active version and the staging-active version. If these are the same, as would be the case often, then the results will be combined, but in the case of a property which matches your query which has different versions for latest, staging and production, you will see 3 entries in the `results` array. So, make sure to deduplicate the results, or filter them to only include the version you are concerned with, e.g. production-active.

## Versioning

The Property API provides a mechanism to create new versions of multiple properties in a single command. However, due to the complexity of the API call, there is not yet a more user-friendly way to do this in PowerShell, so you need to construct the request body directly, either as a JSON string, or as a PSCustomObject/HashTable. Regardless, here is a sample request:

```powershell
$Request = '{
  "createPropertyVersions": [
    {
      "createFromVersion": 1,
      "propertyId": "123456"
    },
    {
      "createFromVersion": 9,
      "propertyId": "234567"
    }
  ]
}'

$BulkVersionRequest = New-BulkPatch -Body $Request
```

or, in a more PowerShell-centric way:

```powershell
$Request = @{
  createPropertyVersions = @(
    @{
      propertyId        = "123456"
      createFromVersion = 1
    },
    @{
      propertyId        = "234567"
      createFromVersion = 9
    },
    @{
      propertyId        = "345678"
      createFromVersion = 24
    }
  )
}

$BulkVersionRequest = New-BulkPatch -Body $Request
```

What this is essentially saying is this:
- Create a new version of property 123456, based on version 1
- Create a new version of property 234567, based on version 9
- Create a new version of property 345678, based on version 24

As mentioned, we don't yet have things like name or version expansion, so you do need to know Property IDs and specific versions, but regardless, the structure of the request is pretty straightforward.

Once the request completes (which typically takes maybe 20s), you can retrieve the results like this:

```powershell
$BulkVersionResults = $BulkVersionRequest | Get-BulkVersionedProperties
$BulkVersionResults

                              versionLink=/papi/v0/properties/prp_574785/versions/133; createVersionSubmitDate=13/08/2026 18:06:45;

                              createVersionStatus=COMPLETE; versionLink=/papi/v0/properties/prp_123456/versions/155; createVersionSubmitDate=13/08/2026 18:06:45;
                              createVersionUpdateDate=13/08/2026 18:06:55}}
```

> Note: you can simply pipe your `$BulkVersionRequest` variable into `Get-BulkVersionedProperties` and the command will extract the necessary parameters automatically. Which is cool. :-)

## Patching

The Property API's bulk patch feature allows you to update the rules of multiple properties in a single command. Property updates are defined using JSONPATCH syntax, which is fairly complex but allows you to make bespoke updates to multiple properties at once. For example, let's say we wanted to complete the following operations in a single command:

- Update the default origin hostname for version 2 of property 123456 to `origin.example.com`
- Remove the first child rule from version 10 of property 234567
- Add the `autoDomainValidation` behavior to version 25 of property 345678

> Note: this example updates 3 properties, but you could also perform 3 updates against the same property, or any other combination you wish.

```powershell
$Request = '{
  "patchPropertyVersions": [
      {
          "propertyId": "123456",
          "propertyVersion": 2,
          "patches": [
              {
                  "op": "replace",
                  "path": "/rules/behaviors/0/options/hostname",
                  "value": "origin.example.com"
              }
          ]
      },
      {
          "propertyId": "234567",
          "propertyVersion": 10,
          "patches": [
              {
                  "op": "remove",
                  "path": "/rules/children/0"
              }
          ]
      },
      {
        "propertyId": "345678",
        "propertyVersion": 25,
        "patches": [
            {
                "op": "add",
                "path": "/rules/behaviors/1",
                "value": {
                    "name": "autoDomainValidation",
                    "options": {
                        "autodv": ""
                    }
                }
            }
        ]
    }
  ]
}'

$BulkPatchRequest = New-BulkPatch -Body $Request
```

In JSONPATCH syntax you have 3 operations you can use.

| Operation | Description |
| --- | --- |
| Add | Adds a new value to the specified path. If the path already exists, the operation will fail. |
| Remove | Removes the value at the specified path. If the path does not exist, the operation will fail. |
| Replace | Replaces the value at the specified path. If the path does not exist, the operation will fail. |

> When using `add` or `replace` the format of the `value` is dependent on what you are adding or replacing. For example, if you are adding a new behavior, the value will be an object with a `name` and `options` property. If you are replacing a simple string, the value will be that string. You do not need to encode the value in any way.

In the above example, the request is defined as a JSON string, but you could also do this as a PowerShell PSCustomObject or Hashtable, like this:

```powershell
$Request = @{
  patchPropertyVersions = @(
    @{
      propertyId        = "123456"
      propertyVersion   = 2
      patches           = @(
        @{
          op    = "replace"
          path  = "/rules/behaviors/0/options/hostname"
          value = "origin.example.com"
        }
      )
    },
    @{
      propertyId        = "234567"
      propertyVersion   = 10
      patches           = @(
        @{
          op   = "remove"
          path = "/rules/children/0"
        }
      )
    },
    @{
      propertyId        = "345678"
      propertyVersion   = 25
      patches           = @(
        @{
          op    = "add"
          path  = "/rules/behaviors/1"
          value = @{
            name    = "autoDomainValidation"
            options = @{
              autodv = ""
            }
          }
        }
      )
    }
  )
}

$BulkPatchRequest = New-BulkPatch -Body $Request
```

Once the request is submitted you must wait for it to complete, typically 30s to 1m, then you can retrieve the results like this:

## Activating

Once you have found your properties, created new versions and patched them, finally you will likely wish to activate them, which you can also do through the Property Bulk options.

> Note: there is a limit to the number of activations you can perform on your account in a single day, which defaults to 500. Production and staging activations both count equally, and the limit applies equally whether you are activating in bulk or with individual activation calls. It can be raised in the back end, which requires a support ticket, but it will take some time so plan accordingly.

A sample bulk activation request looks like this:

```powershell
$Request = '{
    "defaultActivationSettings": {
        "acknowledgeAllWarnings": true,
        "useFastFallback": false,
        "fastPush": true,
        "notifyEmails": [
            "you@example.com",
            "them@example.com"
        ]
    },
    "activatePropertyVersions": [
        {
            "propertyId": "123456",
            "propertyVersion": 2,
            "network": "STAGING",
            "note": "Some activation note"
        },
        {
            "propertyId": "234567",
            "propertyVersion": 10,
            "network": "STAGING",
            "note": "Sample activation",
            "notifyEmails": [
                "someoneElse@somewhere.com"
            ]
        },
        {
            "propertyId": "345678",
            "propertyVersion": 25,
            "network": "PRODUCTION",
            "acknowledgeAllWarnings": false,
            "note": "created by xyz",
            "acknowledgeWarnings": [
                "msg_123",
                "msg_234"
            ]
        }
    ]
}'

$BulkActivationRequest = New-BulkActivation -Body $Request
```

Once the activations are created (note: NOT once the properties are actually activated, which will take much longer), you can retrieve the results like this:

```powershell
$BulkActivationResults = $BulkActivationRequest | Get-BulkActivatedProperties
```

```powershell
        "notifyEmails": [
            "user@akamai.com"
        ],
        "complianceRecord": {
            "noncomplianceReason": "NONE",

            "unitTested": true,
            "customerEmail": "customer@example.com"
        }
    },
    "activatePropertyVersions": [
        {
            "propertyId": "123456",
            "propertyVersion": 2,
            "network": "PRODUCTION",
            "note": "Some activation note"
        }
    ]
}
```
